# Assertion Migration Ledger

Status: fill during implementation

## Purpose

This ledger is the audit trail for the split. It prevents a refactor from
passing validation by replacing broad tests with weaker smoke tests while
silently dropping assertions.

Update this file while moving tests. Do not wait until the end of the split.
Every row should be resolved before the old assertion block or test method is
deleted from its source file.

## Rules

- Record the source method or assertion category before deleting it.
- Record the target module and target test method after the replacement passes.
- Preserve assertion intent. Exact assertion text can change only when the new
  assertion is at least as strict and the reason is recorded.
- Keep strict confirmation, command-journal, close-readiness,
  backend-owned-mutation, and source/root-scope checks visible in target tests.
- Use `N/A` only when an assertion is intentionally deleted, and record why.
- Stop implementation if a row cannot be mapped with confidence.
