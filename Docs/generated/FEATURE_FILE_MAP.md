# Feature File Map

Generated by an AI inventory pass on 2026-06-01. This map is a curated
feature-to-primary-files index for the active V6 workspace. It is not a new
source of truth; pair it with `Docs/generated/PROJECT_INDEX.md` for the
one-row-per-source-file table and with `Docs/inventories/*` for route, DOM,
settings, smoke, and test registries.

## Scope

- Covers active, non-archived V6 runtime, operator, API, WebView/Tauri, tooling,
  validation, and documentation features.
- Excludes vendor binaries, `LocalBase/` runtime state, `Docs/archive/`,
  historical root launcher shims, and generated caches.
- "Primary files" means the files an engineer should inspect first for that
  feature. Support files and exhaustive per-file ownership remain in
  `Docs/generated/PROJECT_INDEX.md`.
- Most rows use full repository-relative paths. Where a row gives a package or
  directory and then short sibling basenames, resolve those basenames inside
  the package already named in the same row.
- Source context used: `AGENTS.md`, `Docs/CURRENT_PROJECT_STATE.md`,
  `OPEN_WORK_CHECKLIST.md`, `Docs/generated/PROJECT_INDEX.md`,
  `Docs/generated/PIPELINE_MAP.md`, `Docs/architecture/MODULE_MAP.md`,

## Known Safety Boundaries to Preserve

- Source mutation is forbidden by default; source files are copied to scratch.
- Backend owns media policy, settings persistence, queue mutation, rename apply,
  pending-publish drain, publish, and process lifecycle.
- WebView/Tauri surfaces may render evidence and submit allowlisted backend
  commands only; they must not implement filesystem mutation or media policy.
- Pending publish parks outputs when final placement is unsafe and drains later
  only with manifest evidence.
- FFmpeg, subtitle, audio, publish/drain, source/scratch/output, and cleanup
  behavior changes require high validation, including representative real-media
  validation where practical.
