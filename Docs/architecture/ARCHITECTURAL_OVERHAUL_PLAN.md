# Media Pipeline Architectural Overhaul

Plan of record. Owner: project maintainer. Authored: 2026-05-28.

This document is the canonical plan for the V6→V7 architectural overhaul.
Execution status lives in `CHANGELOG.md` and in `docs/adr/` once those land.
Do not treat this file as a status tracker — once a phase ships, the ADR is
the source of truth.

---

## Executive Summary

This repository is a Windows-first, single-operator media pipeline (remux,
encode, subtitle, audio, publish) built around a PowerShell engine
(`Pipeline/`), a Python local-API and service layer
(`DesktopApp/mediapipeline_desktop_app/`), a WebView frontend
(`ui_web/static/`), and a Tauri/WebView2 shell. It works, but it is
suffocating under three forms of bloat:

1. **Code fragmentation from prior god-file splits.** Flat directories with
   108 `service_*.py`, 65 `facade_*.py`, and 168 `*.ps1` siblings, named by
   suffix concatenation (for example `facade_settings_patch_candidate.py`,
   `service_queue_dry_run_runner.py`). The natural cohesion of a feature
   is now scattered across 5-15 sibling files with no folder grouping.
2. **Documentation drift industry.** 164 Markdown files plus a 223 KB audit
   CSV plus multiple "single source of truth" claimants
   (`CURRENT_PROJECT_STATE.md`, `OPEN_WORK_CHECKLIST.md`, `AI_HANDOFF.md`,
   `AI_DIRECTIVE.md`, `MONOLITH_SPLIT_PLAN.md`,
   `Docs/CHANGELOG_SUMMARY.md`, `Docs/DOC_TOUCH_LOG.md`,
   `Docs/DOCS_INDEX.md`, `Docs/ARCHITECTURE_SUMMARY.md`,
   `Docs/CURRENT_PROJECT_SUMMARY.md`,
   `Docs/ACTIVE_FIX_CHECKLIST.md`). At least five of these overlap.
3. **Two engines, one job.** The PowerShell pipeline in `Pipeline/Modules/`
   and the Python facade/service tree in
   `DesktopApp/.../application/` both encode pipeline behavior. The Python
   side calls itself a "facade" but holds duplicated state and policy logic.

Recommended direction:

- **Re-fold by domain, not by suffix.** Replace `facade_*.py` / `service_*.py`
  flat trees with `app/<stage>/` packages (`ingest/`, `transcode/`,
  `subtitles/`, `publish/`, etc.). Aim for **~60 Python files in the
  application layer, not 173**.
- **Make Python the orchestrator, PowerShell the executor.** Wrap PowerShell
  modules behind a single contract (`pipeline.exec(stage, payload)`) instead
  of letting both layers know about media policy.
- **Collapse docs to a 5-file canonical set** plus `docs/adr/` plus
  auto-generated summaries. Burn the 107 KB / 141 KB / 223 KB artifacts to
  ADRs plus history.
- **Introduce a `summaries/` directory** with one `<file>.md` per source file,
  generated by a pre-commit hook, so future AI sessions consume ~50 KB of
  summaries instead of ~5 MB of source.
- **Stage the migration in 8 phases** with rollback at each phase. Do not
  big-bang.

The hard claim: this codebase can be reduced by **35-50% in source file
count** and **60-80% in Markdown count** without losing a single shipping
behavior.

## Current-State Audit

### What the pipeline does (observed)

A Plex-style ingest → transcode → publish loop for a single operator on
Windows:

- Scans configured source roots for movies and TV.
- Copies sources to a scratch dir (source mutation forbidden by default).
- Probes media with `ffprobe`/MediaInfo-style logic, decides remux vs
  encode.
- Runs FFmpeg (vendored at `Pipeline/Tools/ffmpeg/bin/ffmpeg.exe`),
  MKVToolNix, PgsToSrt for subtitles.
- Routes audio (passthrough/downmix/transcode) by profile.
- Renames using a TV/movie parser (`Pipeline/Modules/Naming.*.ps1`).
- Writes sidecars and manifests, publishes to a final root, or *parks*
  output in "pending publish" when the final root is unsafe and drains
  later.
- Exposes operator controls via a local Python HTTP API to a WebView UI
  (vanilla JS) shipped via a Tauri/WebView2 shell.
- Has an optional coordinator/worker network mode
  (`DesktopApp/.../network/`) — currently read-only from the UI.

### Main components

| Component             | Location                                                  | Role                                                            |
| --------------------- | --------------------------------------------------------- | --------------------------------------------------------------- |
| PowerShell engine     | `Pipeline/Modules/` (168 modules)                         | All media policy, FFmpeg invocation, queue/probe/audit          |
| Python service layer  | `DesktopApp/.../service_*.py` (108 files)                 | State, config, status, telemetry, process lifecycle adapters    |
| Python facade layer   | `DesktopApp/.../application/facade_*.py` (65 files)       | DTOs plus use-cases consumed by the API                         |
| Local API             | `DesktopApp/.../api/` (40 files)                          | HTTP routes, command journal, payload contracts                 |
| WebView frontend      | `DesktopApp/.../ui_web/static/`                           | Vanilla-JS panels (Queue, Launch, Settings, Diagnostics, etc.)  |
| Tauri shell           | `DesktopApp/tauri_shell/`                                 | WebView2 wrapper plus lifecycle scripts                         |
| Schemas               | `Pipeline/Schemas/` (10 JSON schemas)                     | Contracts for completed jobs, manifests, progress, events       |
| Tests                 | 212 Python tests plus 6 PS1 integration suites plus Unit/ | Heavily skewed to API/facade unit tests                         |
| Bundled tools         | `Pipeline/Tools/`, `Pipeline/PowerShell-7.6.0-win-x64/`   | ffmpeg, ffprobe, MKVToolNix, PgsToSrt, PowerShell 7.6 (ignored) |

operator

### Config flow

- `Pipeline/MediaPipeline_config_chatgpt.psd1` (PowerShell data file) is the
  **authoritative** runtime config.
- A second representation lives in
  `DesktopApp/.../config_schema.py` plus four sibling
  `config_schema_*.py` files plus
  `DesktopApp/.../service_config_psd1.py` for read/write of the PSD1.
- The WebView consumes a third representation as JSON over the API.
- **Three representations of the same shape** with no shared schema
  generator. Classic drift surface.

### External tools

`ffmpeg`, `ffprobe`, `MKVToolNix`, `PgsToSrt` (all vendored). PowerShell 7.6
vendored. No `MediaInfo`, no `ExifTool`, no `rclone`/`rsync`, no DB. State
is JSON files in `LocalBase/State/`.

### Main pain points

1. **Service/facade explosion.** Look at one feature, "settings".
   `facade_settings.py`, `facade_settings_helpers.py`,
   `facade_settings_patch.py`, `facade_settings_patch_candidate.py`,
   `facade_settings_patch_policy.py`, `facade_settings_policy.py`,
   `facade_settings_profile.py`, `facade_settings_risk.py`,
   `facade_settings_wizard.py` plus `service_config*.py` (12 files) plus
   `settings_risk_policy.py`, `settings_risk_policy_rules.py`. **22+ files
   for one feature**, all siblings.
2. **Audit/process naming.** `service_audit_rerun.py`,
   `service_audit_rerun_csv.py`, `service_audit_rerun_export.py`,
   `service_audit_rerun_io.py`, `service_audit_rerun_metadata.py`,
   `service_audit_rerun_records.py`. These belong in
   `audit/rerun/{csv,export,io,metadata,records}.py`.
3. **PowerShell modules named with dotted suffixes** (`Audit.Audio.ps1`,
   `MediaProbe.SubtitleParity.ps1`, `Subtitles.Common.Config.ps1`). They
   mimic folders without being folders. 168 files in one directory.
4. **Doc proliferation.** 164 Markdown files. At least 5 claim "single
   source of truth." `MONOLITH_SPLIT_PLAN.md` is 141 KB. `AI_HANDOFF.md`
   is 107 KB. `md_documentation_audit.csv` is 223 KB. `Docs/archive/` has
   80 files. The fact that there is a `Docs/DOC_TOUCH_LOG.md` is itself a
   drift symptom.
5. **Root clutter.** ~30 files at the repository root: 5 status `.md`,
   7 `.bat` launchers, 4 root `.ps1`, plus `fragment_check.py`,
   `md_documentation_audit*`, `New-RealMediaValidationWorksheet.ps1`. Root
   should be ~10 entries.
6. **Two changelogs and no real changelog.** `CHANGELOG_SUMMARY.md`,
   `DOC_TOUCH_LOG.md`, plus per-feature implementation reports
   (`COORDINATOR_WORKER_*REPORT.md`, `OBSERVABILITY_AND_SECRETS_FIXES.md`,
   `SETTINGS_WIZARD_REVIEW_FIXES.md`).
7. **No DB.** State is JSON files. Queue snapshots, command journal, and
   audit history all want a real index for filtering, age queries, and
   recovery; SQLite would replace ~10 JSON-file readers/writers.
8. **No structured logging contract.** Logs are PS1-printed text under
   `RunLogs/`. Diagnostics is built by re-parsing logs. Fragile.
9. **Modified-files state.** `git status` shows ~200 modified files with no
   staged commit, plus a deleted `DOCS_HOUSEKEEPING_AUDIT.md`. The repo
   carries uncommitted churn from a doc-cleanup pass that has not landed.
10. **Vendored PowerShell 7.6 in `Pipeline/PowerShell-7.6.0-win-x64/`.**
    It is gitignored but the directory still exists locally. If it ever
    got committed historically, repo history is heavy.
11. **`Pipeline/__pycache__/`** committed at some point.
12. **One-shot Python at root** (`fragment_check.py`,
    `md_documentation_audit.csv`) should not live in the repo root.

- `DesktopApp/mediapipeline_desktop_app/application/` — 65 facade files

- `DesktopApp/mediapipeline_desktop_app/` (flat) — 108 service files where

5. **Schemas in `Pipeline/Schemas/*.json` ↔ Python dataclasses in

6. **Test names ↔ actual module names** after splits.

| Module           | Owns                                                | Does not own                       |
| ---------------- | --------------------------------------------------- | ---------------------------------- |

| `orchestration/` | Job lifecycle, queue, scheduling, retries           | Media decisions, file moves        |
| `ingest/`        | Source discovery, scratch copy, dedupe              | Probing decisions, output paths    |

| `storage/`       | SQLite state DB, locks, path layout                 | Business logic                     |
| `network/`       | Coordinator/worker                                  | Pipeline decisions                 |
| `observability/` | Logs, journal, metrics, telemetry                   | Business decisions                 |
| `config/`        | Schema, load/save, drift checks                     | Runtime state                      |
| `contracts/`     | Pydantic models, schema generation                  | Behavior                           |

### Naming conventions

- Folders name domains (`subtitles/`, `publish/`). Files name roles
  (`subtitles/srt.py`, `publish/drain.py`).
- No suffix-concatenated filenames.
- No `_chatgpt`, `_v2`, `_new` suffixes.
- PowerShell module files: `engine/<domain>/<role>.ps1`. No dotted suffixes.
- Tests mirror source paths: `tests/python/unit/publish/test_drain.py`.
- ADRs: `docs/adr/NNNN-short-slug.md`.
- Schema files: `schemas/<contract>.v<n>.schema.json`.

### Config strategy

- **One authoritative source**: `app/contracts/config.py` (pydantic).
- `config/default.psd1` is a *seed* file shipped with the product.
- Runtime config is a single file: `state/config.psd1` (or `.json`; pick
  one).
- Python `config/load.py` parses to the pydantic model.
  `config/save.py` writes back. PowerShell engine receives config as JSON
  via stdin; never reads PSD1 directly.
- **Schema generation**: `schemas/config.v1.schema.json` is generated from
  the pydantic model in CI. Drift = CI fail.

### Logging strategy

- All Python logs through `structlog` (or stdlib `logging` with a JSON
  formatter); one line = one JSON record.
- PowerShell engine logs to stdout/stderr as JSON lines
  (`{"ts":..., "stage":..., "level":..., "msg":..., "data":{...}}`).
- The orchestrator reads JSON lines and persists them to `state.sqlite`
  (table: `events`). Diagnostics queries that table; no log scraping.
- One log file per run: `runlogs/<run_id>.jsonl`. Auto-rotated.

### Error handling strategy

- Custom hierarchy:
  `MediaPipelineError → {IngestError, ProbeError, RoutingError,
  TranscodeError, SubtitleError, AudioError, PublishError, RenameError,
  NetworkError, ConfigError}`.
- Each carries a `code` (machine-readable, stable) and `context` (dict,
  structured). API maps to HTTP code by exception type.
- Never log-and-swallow. Either retry, mark failure with code, or re-raise
  to the orchestrator.
- Backend never returns 500 with unstructured trace; always
  `{"error": {"code", "message", "context"}}`.

### Retry strategy

- Centralized in `common/retries.py`. Per-stage policy: ingest = 3 with
  backoff, transcode = 1 (expensive), publish/drain = 5 with backoff,
  network = 5 with jitter.
- Retries persisted to the journal so re-runs are observable.

### Metadata strategy

- `app/contracts/` holds the canonical pydantic models for `MediaSource`,
  `Probe`, `RouteDecision`, `TranscodeAttempt`, `Sidecar`,
  `CompletedJob`, `PendingPublish`.
- `schemas/` is generated. Pipeline events validate against schemas at API
  boundaries via `jsonschema`.
- Probe output cached in SQLite (table: `probe_cache`, keyed by
  `(path, mtime, size)`).

### Storage strategy

- `state/state.sqlite` replaces ~80% of the existing JSON state files:
  `queue_snapshots`, `jobs`, `attempts`, `events`, `commands`,
  `pending_publish`, `completed`, `audit_records`, `probe_cache`,
  `config_history`.
- File state files retained only for things genuinely external
  (e.g. `pending_publish/<id>/manifest.json` next to the parked payload).
- Locks: filesystem advisory lock (`filelock`) plus DB row lock for the
  active job.

### Testing strategy

- **Unit** (`tests/python/unit/`): pure logic, no I/O. Every commit.
- **Contract** (`tests/python/contract/`): every API route and stage I/O
  validated against `schemas/*`. Every commit.
- **Integration** (`tests/python/integration/`): real SQLite, real
  subprocess, fake media. Every PR.
- **Smoke** (`tests/python/smoke/`): WebView plus Tauri prereqs plus
  healthcheck. Every PR plus nightly.
- **Real-media** (`tests/realmedia/`): operator-driven, never CI.
- Drop the 1:1 `test_application_facade_<name>.py` pattern. Group tests by
  *behavior*, not by source file.

### Documentation strategy

- Canonical root Markdown plus `Docs/`:
  - `README.md` — install, launch, top-level pointers.
  - `CHANGELOG.md` — keepachangelog format. **Only** place ordered changes
    live.
  - `AGENTS.md` — AI entry point.
  - `OPEN_WORK_CHECKLIST.md` — interim unresolved work queue.
  - `Docs/architecture/ARCHITECTURE.md` — diagram plus module boundaries.
  - `Docs/generated/PIPELINE_MAP.md` — stage I/O contracts (generated).
- `Docs/adr/` — every architectural decision, immutable once accepted.
- `summaries/` — generated.
- Everything else consolidates or moves to `Docs/archive/`.

## Recommended Tools and Programs

For each: **Why it fits**, **What it replaces**, **Required vs optional**,
**Complexity delta**.

### Required additions

**SQLite (via `sqlite3` stdlib or `sqlmodel`/`aiosqlite`).** Replaces ~10
JSON state files with one queryable file; durable command journal, queue
history, probe cache, completed audit log. Replaces
`service_queue_snapshot.py`, `service_status_*` readers/writers,
`service_audit_rerun_records.py`, `service_completed_manifest.py`,
`command_journal.py` storage. Required. Complexity: lower long-term.

**`pydantic` v2.** Single source of truth for contracts; auto-generates
JSON schemas; validates at API boundaries. Replaces hand-rolled
`contracts/*.py` validation and `config_schema*.py` fan-out. Required.
Complexity: lower long-term.

**`structlog` plus JSON logging.** Structured logs the orchestrator can
store in SQLite; eliminates log-scraping in Diagnostics. Replaces ad-hoc
log printing in PS modules, `service_telemetry_*`, log-parsing in
Diagnostics. Required. Complexity: low.

**`jsonschema`.** Validate API payloads against generated schemas; catch
contract drift at runtime. Replaces hand-rolled validation in
`command_payloads_*.py`. Required. Complexity: low.

**`pre-commit` extended with: ruff, mypy, schema-sync, summary-sync.**
Prevents drift at commit time. Already partly present
(`.pre-commit-config.yaml`). Required (extend). Complexity: low.

### Strongly recommended

**`MediaInfo` CLI** (alongside `ffprobe`). Better technical metadata for
some container quirks. Bundle alongside ffmpeg. Optional.

**`Just` (or keep `.bat` if cross-platform isn't a goal).** Replaces ~10
root `.bat` files with one `justfile`. Optional but high readability win.

**`taskipy` or `nox`.** All-Python alternative to Just.

**`mkdocs` plus `mkdocs-material`.** Render `docs/` into a navigable static
site. Optional.

### Optional or situational

**`rclone`** — only if remote-storage publish becomes a goal.

**`Dagster` / `Prefect` / `Celery` / `RQ`** — *avoid* for now. Single-
operator pipeline. Reach for `Dagster` if multi-host coordination becomes a
hard requirement.

### Navigation and generated files

### Summary file format (per source file)

```markdown
---
file: app/publish/drain.py
pipeline_stage: publish
token_priority: high
last_reviewed: 2026-05-28
last_modified: 2026-05-24
sha256: a3f1...
owner_domain: publish
related: [app/publish/pending.py, app/storage/db.py, engine/publish/]
---
# app/publish/drain.py

**Purpose:** Move parked outputs from pending-publish into the published
root, with manifest evidence and rollback on failure.

**Key responsibilities:**
- Read pending-publish manifest.
- Acquire publish lock.
- Move payload plus sidecars atomically.
- Emit drain event to journal.

**Inputs:** `PendingPublishId`, `DrainOptions` (pydantic).
**Outputs:** `DrainResult` with `{moved, skipped, failed, manifest_path}`.

**Important symbols:**
- `drain(pending_id, options) -> DrainResult`
- `class DrainResult(BaseModel)`
- `_acquire_publish_lock()`  # internal

**Dependencies (in-repo):** `app/publish/pending`, `app/publish/manifest`,
`app/storage/db`, `app/storage/locks`.
**Side effects:** Filesystem move; SQLite write to `events` and `published`
tables; advisory lock.
**Config used:** `publish.final_root`, `publish.drain.parallelism`,
`publish.drain.allow_overwrite`.
**Pipeline stage:** publish/drain (`schemas/drain.v1.schema.json`).
**Known risks:** Same-disk move vs cross-disk copy; pending manifest
desync; final-root unavailable.
**Token priority:** high — read before editing publish behavior.
```

### Token-priority taxonomy

- **High** — pipeline-critical, behavior-defining. Read full file when
  editing related area.
- **Medium** — adapters, DTOs, route handlers. Summary suffices; read full
  only when editing this file.
- **Low** — generated, vendored, pure glue.

### Rules for future AI sessions

1. Start by reading `Docs/generated/PROJECT_INDEX.md`,
   `Docs/architecture/ARCHITECTURE.md`,
   `Docs/generated/PIPELINE_MAP.md`, plus the relevant slim backlog file.
2. For each file you intend to edit, read its summary in `summaries/`.
3. Only open the full source if the summary marks it `high` or the change
   requires reading a function the summary did not list.
4. After editing, run `just refresh-summaries` (or pre-commit does it).
5. Do not duplicate long code blocks into summaries.
6. Track file ownership via `owner_domain` in frontmatter.
7. Maintain a context budget of ~80 KB summaries plus ~50 KB full sources
   per task.

### Automated summary refresh

A script `scripts/dev/refresh_summaries.py`:

1. `git diff --name-only HEAD~1` (or `--cached` for pre-commit).
2. For each changed Python/PS file:
   - Parse (Python `ast`, PS regex or PSScriptAnalyzer AST).
   - Extract module docstring, public symbols, decorated routes, imports.
   - Render summary to `summaries/<path>.md`.
   - Update `sha256` in frontmatter.
3. Refresh `Docs/generated/PROJECT_INDEX.md` if summaries added/removed/renamed.
4. Refresh `Docs/generated/DEPENDENCY_GRAPH.md` if imports changed.
5. CI: if any source `sha256` in summary differs → fail.

## Risks and Tradeoffs

| Risk                                                       | Likelihood | Impact | Mitigation                                                            |
| ---------------------------------------------------------- | ---------- | ------ | --------------------------------------------------------------------- |
| Re-fold introduces import errors                           | M          | H      | One-domain-at-a-time; shims for one release; integration smoke/phase  |
| PSD1 ↔ pydantic round-trip loses comments/order            | M          | M      | Custom serializer plus round-trip golden test                         |
| SQLite contention under coordinator/worker                 | L          | M      | WAL mode; one writer per process; advisory file lock                  |
| Operators rely on deleted `.bat` from muscle memory        | H          | L      | Redirect `.bat` files for one release; document in CHANGELOG          |
| AI sessions keep writing old-style files                   | M          | M      | `AGENTS.md` loaded by Claude Code; naming lint blocks bad names       |
| Phase 6 deletes something a hidden script imports          | L          | H      | Deprecation shim; smoke plus release gate                             |
| PS engine has hidden inter-file ordering                   | M          | H      | Move in domain batches; internal include order preserved; tests       |
| ADR rule annoys contributors                               | M          | L      | Warning, not block; relax for trivial PRs                             |

**Tradeoffs chosen:**

- SQLite over Postgres — single-operator simplicity.
- Pydantic over manual contracts — generated schemas.
- Vanilla JS over framework — deferred (ADR-0007).
- Keep PowerShell engine — rewriting FFmpeg orchestration is a year of
  risk.
- No workflow engine — scale doesn't justify.
- No Docker — Windows + NVENC + UNC paths.
- MediaInfo as optional addition.
