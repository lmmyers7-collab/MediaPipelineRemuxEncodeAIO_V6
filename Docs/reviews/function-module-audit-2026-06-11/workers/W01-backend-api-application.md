## Detailed Findings

### W01-001 - Medium - Cluster log line injection through unsanitized worker log fields

- **File / line / symbol:** `src/mediapipeline/desktop/network/cluster_log.py:19` and `src/mediapipeline/desktop/network/cluster_log.py:21`, `format_cluster_log_line()`. Supporting path: `src/mediapipeline/desktop/network/protocol.py:299` (`LogEntryRequest.from_dict()`), `src/mediapipeline/desktop/network/identity.py:34` (`sanitize_log_entry_fields()`), and `src/mediapipeline/desktop/network/coordinator_http_handlers.py:398` (`_http_log()`).
- **Problem:** `/api/log` accepts string fields from authenticated workers, `LogEntryRequest.from_dict()` converts them with `str(...)`, `sanitize_log_entry_fields()` bounds identity/event/message length but does not normalize CR/LF, and `format_cluster_log_line()` interpolates `worker_name` and `entry.message` directly before appending one trailing newline.
- **Impact:** A worker with the shared coordinator token can forge extra apparent rows in `cluster.log`. That weakens operator diagnostics for network-mode events, auth failures, claim/done order, and post-failure triage. This is observability integrity, not direct media mutation.
- **Evidence:** The formatter uses `(entry.worker_name or entry.worker_id[:8] or "?")[:20]` at `cluster_log.py:19`, puts `entry.message or ""` into the formatted row at `cluster_log.py:21`, and returns that text plus `"\n"` at `cluster_log.py:29`. `sanitize_log_entry_fields()` only clears invalid IDs, truncates long worker names, truncates event length, and truncates message length at `identity.py:34-44`. A direct probe with `worker_name="Worker\nFORGED"` and `message="ok\n2026-01-01  ERROR forged"` produced 3 physical output lines from one `format_cluster_log_line()` call.
- **Fix direction:** Normalize CR/LF and other control characters for all cluster-log display fields before formatting, preferably in `sanitize_log_entry_fields()` and defensively in `format_cluster_log_line()`. Preserve bounded diagnostics but guarantee one event writes exactly one physical line.
- **Validation:** Add tests for `format_cluster_log_line()` and `_http_log()` that submit CR/LF in `worker_name`, `role`, `level`, `event`, `message`, `job_id`, and `source_path`; assert the rendered string has one line and still includes safe diagnostic text. Then run targeted network coordinator HTTP/runtime tests.
