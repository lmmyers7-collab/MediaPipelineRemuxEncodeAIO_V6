# Tauri/WebView2 Daily-Use Parity Matrix

Date: 2026-05-14

Scope: V5 CustomTkinter fallback shell versus the WebView/Tauri preview shell. This matrix tracks practical operator parity only. Tk remains the supported fallback. WebView mutation flows must use backend-owned local API commands.

## 2026-05-15 Addendum

- Completed output-size review now consumes recorded backend `size_policy` metadata from completed sidecars. The WebView can distinguish compatibility growth that stayed within the backend-selected policy limit from actual exceeded/advisory/strict size-guard rows, instead of relying only on a legacy hardcoded +5% warning line.
- `/api/contract` now publishes design-only repair/reconcile contracts with mutation disabled for Completed manifest reconciliation, Completed sidecar repair, Pending Publish manifest repair, and orphan payload reconciliation. WebView API Contract safety review displays those boundaries, but no repair route or mutation control was added.
- Settings Subtitle now shows backend-authored BDPGS OCR tool/tessdata path evidence from `/api/settings/workspace`, including saved-config path resolution, existence, expected kind, `.dll`/`dotnet` posture, and ready/review/blocked state. No WebView path picker or frontend path resolver was added.
- Settings now includes a read-only `Raw-Key Action Plan` that turns raw-key triage into operator next steps: schema drift, BDPGS OCR path evidence, subtitle keyword builder coverage, intentionally excluded auth secrets, remaining advanced raw keys, and backend-owned save boundaries. It cannot stage JSON, save config, edit secrets, resolve arbitrary paths, run OCR/FFmpeg, launch, drain, publish, rename, or touch media.
- Home External Dependency Digest and Diagnostics First Response now surface the loaded Settings Raw-Key Action Plan alongside OCR path and toolchain evidence. This makes raw-key schema drift/high-review posture visible during triage without adding settings-save, secret-edit, path-picker, OCR-run, launch, publish/drain, rename, repair, or media-mutation authority.
- Diagnostics First Response and Completed owner-row handoff now surface saved-policy reconciliation evidence from Home/Completed. The path points operators to Home Sample Validation, Completed Selected Pilot Evidence Packet, and Settings media policy before accepted evidence or rerun decisions, while remaining local/read-only.
- Launch now includes a read-only `Pilot Run Readiness` panel that condenses selected Queue sample, saved Settings policy, backend preflight, pilot category coverage, real-media proof plan, sample execution checklist, Pending Publish posture, post-run proof plan, and mutation boundary before a real-media pilot. It does not change Start behavior, queue scope, settings, publish/drain, rename, validation append, or media files.
- Completed now includes a read-only `Selected Pilot Evidence Packet` that turns the selected Completed row's output/sidecar proof, route/size/audio/subtitle evidence, Pending Publish/final-placement proof, Diagnostics/runtime context, Sample Validation readiness, manual playback checks, and mutation boundary into a copyable Markdown post-run checklist. It adds no backend route or mutation control.
- Completed Real-Media Output Proof and Selected Pilot Evidence Packet now include `Saved policy reconciliation`, a post-run companion to Launch's pre-run policy-vs-route evidence. It compares completed route, size policy, audio/subtitle decisions, and final-placement proof against saved policy-alignment categories while remaining read-only.
- Home Sample Validation now includes a read-only `Completed Evidence Handoff` that mirrors the Completed Selected Pilot Evidence Packet before Preview/Append. It exposes packet status, saved-policy reconciliation status/detail, selectable proof rows, detail text, and copyable Markdown without adding validation append, accept-output, rerun, drain, publish, repair, settings-save, rename, manifest-write, media-policy, or filesystem mutation authority.
- Home Sample Validation now includes a read-only `Acceptance Readiness Gate` before Preview/Append. It makes accepted-evidence blockers/review items visible from selected sample proof, checklist coverage, Completed packet posture, backend validation-log state, manual playback/media checks, and backend-only mutation boundaries, while leaving backend Preview/Append authoritative.
- Home Sample Validation now includes a read-only `Accepted Record Proof Review` for the selected/current accepted validation record. It compares record identity, Completed output/sidecar, size/output-growth, subtitle/audio, Diagnostics/run-log, Pending Publish/final placement, and current reconciliation evidence so stale historical notes do not look equivalent to current proof.
- Home Sample Validation now includes a read-only `Pilot Category Validation Summary` that groups H.264 remux, subtitle SRT generation, audio routing, encode/size policy, and deferred publish categories by current accepted evidence, worksheet-only plans, historical accepted records, stale/review records, and missing/planned coverage.
- `/api/sample-validation` and Home now include a backend-authored `Real-Media Validation Audit` roll-up. It summarizes readiness, current/stale record reconciliation, generated worksheet context, representative category coverage, evidence gaps, pilot runbook, and cutover posture in one conservative status while remaining unable to launch, append, accept, repair, publish/drain, save settings, rename, rewrite manifests, or touch media.
- `/api/sample-validation` and Home now include a backend-authored `Real-Media Policy Alignment` roll-up. It maps saved Settings media-policy readiness to required pilot categories for H.264 remux, subtitle-to-SRT, audio routing, encode/size, and deferred publish before pilot evidence is trusted. It cannot save settings, alter policy, launch, append, publish/drain, repair, rename, rewrite manifests, run FFmpeg, or touch media.
- Launch now mirrors that policy alignment beside the selected/representative Queue route in `Saved policy vs Queue route` rows. The comparison is read-only and advisory: it can show visible route signals for H.264 remux/encode-size policy and call out missing subtitle/audio/deferred-publish route tokens, but backend Start and post-run proof remain authoritative.
- WebView Network now includes a read-only `Network Lifecycle Handoff` that combines close-readiness, Network role/auth/path-map configuration, persisted worker claim health, pending done reports, runtime state-file metadata, diagnostics route availability, `/api/contract` design-only lifecycle contracts, and future promotion requirements. It keeps coordinator/worker start, stop, retry, reclaim, release, abort, settings-save, state-write, queue, publish, rename, and media mutation outside the WebView.
- Diagnostics `First Response Checklist` rows are now selectable. Row detail explains why each gate matters, lists the evidence behind refresh health, close-readiness, ActiveJobs/progress, state artifacts, dependencies, command issues, owning-page handoff, malformed logs, and mutation boundaries, and keeps Diagnostics evidence/navigation-only before any owner-page command.
- Queue Launch Decision, Completed Output Acceptance, and Pending Publish Drain Decision summaries now lead with a daily-use handoff, operator outcome, and explicit scope boundary. This makes it harder to mistake filtered/selected rows, proof boards, recovery dry-runs, or 250-row caps for backend launch, output acceptance, or drain scope. No backend route, mutation command, media policy, or filesystem behavior changed.
- The Tauri pre-window asset gate now requires Launch pilot-readiness fragments and its mocked validation fixture serves the already-required Pending Publish script, keeping the shell check aligned with current WebView assets.
- Diagnostics State Artifact Summary now surfaces blocked/review BDPGS OCR tool/tessdata evidence from saved backend config as a `settings_bdpgs_ocr_paths` read-order row when OCR is enabled. This handoff points operators to Settings > Subtitles without giving Diagnostics any settings-write, arbitrary path-read, OCR-run, or media-mutation authority.
- Maintenance now includes backend-authored toolchain readiness evidence over the existing health rows. The WebView shows PowerShell/ffmpeg/ffprobe/MKVToolNix/GPU telemetry/subtitle-helper capability, source, required/optional posture, failure scope, and real-media proof boundary without adding install, PATH edit, arbitrary tool resolution, launch, package-write, manifest-write, or media mutation controls.
- Home and Diagnostics now include a read-only external dependency digest/checklist row that joins Settings OCR path evidence, Diagnostics OCR handoff rows, and cached Maintenance toolchain evidence. It does not poll `/api/maintenance` during the 4-second refresh loop; Maintenance evidence appears only after the operator opens/runs Maintenance.
- `/api/sample-validation` and Home now include a backend-authored WebView Cutover Gate. It rolls up current accepted sample records, required/recommended validation checks, stale-history posture, worksheet context, and pilot-plan state into a conservative `pilot-needed` / `review` / `blocked` / `ready-for-operator-trial` posture. It is not a production cutover switch and cannot mutate media or pipeline state.
- `/api/sample-validation` and Home now include a backend-authored Real-Media Sample Set Guide. It gives the operator a representative 3-5 file pilot checklist across H.264 remux/direct-play, subtitle-to-SRT, audio routing/default language, encode/size policy, and deferred publish/final placement while keeping launch, acceptance, publish/drain, settings save, rename, and media mutation backend-owned or absent.
- The cutover and sample-set payloads explicitly distinguish generated worksheets from accepted validation records. Worksheet rows can make sample/category coverage planned and visible, but they cannot satisfy current accepted record counts, category-ready status, or WebView trial readiness without an accepted validation record that still reconciles to backend proof.
- Home now has an explicit local `Use Selected Category` handoff from the Real-Media Sample Set Guide into the Sample Validation Pilot Category selector, and the records table shows persisted record categories plus current-evidence status and missing-proof counts. This only changes local/display evidence form state; backend preview/append still owns validation and no media/pipeline mutation is added.
- Home Sample Validation now includes a backend-authored `Real-Media Evidence Gaps` board. It distills readiness, reconciliation, worksheet, pilot-plan, cutover, and sample-set evidence into rows for current backend proof, selected sample/saved policy, post-run Completed/Diagnostics proof, Pending Publish/final placement, manual playback/subtitle/audio checks, representative category coverage, current accepted-record reconciliation, and worksheet context. It is read-only and cannot launch, append, accept, repair, drain, publish, save settings, rename, rewrite manifests, or touch media.
- Home Sample Validation now includes a backend-authored `Real-Media Pilot Runbook` packet. The WebView renders runbook status, step rows, selected-step details, and copyable Markdown text generated from existing backend sample-validation evidence. It is an operator checklist/export surface only and does not write files, launch, append, accept, repair, drain, publish, save settings, rename, rewrite manifests, or touch media.
- Home Preview Record and Append Evidence Record results now include backend-authored `Post-Run Evidence Capture` output. It converts the selected sample preview into a copyable checklist for route decision, Completed proof, Diagnostics/FFmpeg proof, Pending Publish/final placement, subtitle behavior, audio behavior, size posture, and append decision. It is display/copy guidance only; append behavior and all mutation boundaries remain unchanged.
- Completed, Pending Publish, and Diagnostics selected-row details now include read-only Sample Validation comparison lines over the already-loaded Sample Validation payload. They show matching records, accepted/current/stale/review counts, missing current-evidence fields, and post-run capture guidance without adding append, accept, rerun, drain, publish, repair, save, rename, manifest-write, or media-mutation authority.
- Pending Publish selected-row detail now includes a read-only Sample Validation handoff for the `deferred-publish` pilot category. It tells the operator whether parked-output evidence should stay `hold_review` or can support an accepted evidence note only after Completed output proof, durable drain-summary proof, and logs agree.
- Pending Publish now includes a read-only `Post-Drain Trust Review` panel. It keeps post-drain proof separate from the pre-drain button guard by correlating current parked rows, durable drain summary, recent drain events/logs, Completed output proof, Sample Validation deferred-publish posture, and latest drain-command evidence before an operator trusts a drained sample, retries publish, or records acceptance evidence.
- Browser/DOM smoke hardening now proves guide row selection is review-only until the handoff button is clicked, verifies alternate category handoff, and checks Pending Publish handoff wording for both ready-looking and blocked parked-output evidence.
- Launch now includes a read-only `Real-Media Sample Proof Handoff` that mirrors Home `Real-Media Validation Worksheet` evidence before start decisions.
- The Launch handoff shows sample identity, Queue route intent, Completed output/sidecar/size proof, Diagnostics run evidence, Pending Publish/final destination posture, Settings saved-policy posture, Home Sample Validation evidence, and the Launch mutation boundary.
- Launch now explicitly labels that handoff as pre-run intent context only. Completed's Real-Media Output Proof ladder includes a matching `Launch-to-output transition` checkpoint so the operator sees that finished-output trust must come from post-run Completed, Pending Publish, Diagnostics, playback, and Sample Validation proof.
- Completed now has a read-only `Final Output Trust Walkthrough` that puts selected-row final proof in one ordered handoff: Completed Manifest row, output/sidecar disk state, Pending Publish/drain final placement, Plex/media policy evidence, Diagnostics/log proof, and Sample Validation preview boundary. It is decision support only and cannot accept, repair, rerun, drain, publish, delete, save settings, rename, rewrite manifests/sidecars, or touch media.
- Diagnostics owning-page handoff now maps flagged Completed rows to the matching `Final Output Trust Walkthrough` step before local owner-row navigation. Missing output/sidecar evidence maps to step 2, pending/drain evidence to step 3, route/size/media/audio/subtitle evidence to step 4, runtime/log evidence to step 5, and sample-validation/acceptance evidence to step 6. `Go To Owner Row` locally selects the Completed row and mapped final-trust step when the Completed helper is loaded. This keeps Diagnostics as read-only triage while Completed remains the owner of final output trust decisions.
- Completed/Pending proof and backend publish reconciliation now classify final-placement conflicts separately from no-proof missing outputs. Missing Completed outputs with exact Pending Publish proof remain review-only parked/deferred evidence; missing outputs with exact durable drain-summary proof remain review-only final-placement conflicts; missing outputs with neither stay blocked as no-proof. No repair/reconcile/drain/publish mutation controls were added.
- Command Results and Diagnostics command drilldown now surface the same final-placement proof for pending-publish, drain, publish, and missing-output command contexts. Selected command detail and the Command Failure Resolution Checklist show whether cached Completed/Pending evidence indicates still-parked output, durable drain-summary proof, or no-proof missing output before the operator repeats a drain, reruns a source, or cleans up. This is read-only correlation over already-loaded Completed/Pending proof and backend command data.
- Launch also mirrors Home's backend-authored Sample Validation execution checklist so the start surface shows before-launch sample/policy checks, backend Launch boundary, post-run Completed/Diagnostics/Pending Publish proof, and evidence-record steps before a pilot run.
- Launch also includes a compact Pilot Run Readiness checklist that rolls Queue, Settings, backend preflight, Sample Validation category coverage, Pending Publish posture, and post-run proof expectations into one Launch-surface operator decision aid.
- The evidence is rendered from the same `crossPageContext` passed to Home cross-page context, reducing proof-logic drift between Home and Launch.
- `Test-WebViewBrowserLaunchQueueReadinessSmoke.ps1`, `test_application_facade`, and `test_webview_real_media_smoke` now verify the Launch proof handoff and pilot-readiness panel while preserving the no-POST/no-media-mutation boundary.

## 2026-05-14 Addendum

- `/api/schedule` now includes read-only `continuous_watcher` state from the backend watcher manager. Schedule Coverage Review has a selectable `Continuous watcher` row, Schedule Timing Trust shows current watcher status/deadline, and Launch readiness echoes the same state before start decisions.
- This visibility is evidence-only. Schedule/Launch cannot directly arm the watcher, write stop flags, start work, or mutate schedule gates; backend Launch start and process-control routes remain authoritative.
- Close-readiness now treats an armed backend schedule-stop watcher as active work. This prevents the shell from presenting a safe close while closing would cancel the future stop-at-schedule-boundary guard.
- `desktop_close_readiness.v1` now carries structured `continuous_watcher` evidence, and warning `backend.shutdown` command results preserve the same watcher state plus close reason. Diagnostics/Backend Lifecycle can now show watcher status/PID/deadline directly instead of relying only on free-text reason parsing.
- `Test-WebViewBrowserLifecycleSmoke.ps1` now proves the real backend-served WebView blocks backend shutdown while the watcher is armed, avoids confirmation/backend POST in that blocked path, and posts backend-owned `/api/backend/shutdown` only after safe close-readiness plus confirmation.
- The Tauri shell now consumes `continuous_watcher` in native close-readiness prompts too, and its startup WebView asset gate checks for Backend Lifecycle/Close Readiness/shutdown-guard fragments before a preview window opens.
- Backend-started WebView `continuous` pipeline runs now have a backend-owned schedule-stop watcher. When schedule enforcement is on, the request is inside the allowed window, `Ignore Schedule` is not selected, and the current schedule payload has a window end, backend start arms a daemon watcher that writes the normal stop flag at the boundary if the process is still running.
- `Ignore Schedule` remains a high-review bypass and does not arm the watcher. If the local API process is killed before the deadline, the in-process watcher cannot request a later stop.
- Launch backend preflight now includes a backend-authored `Continuous schedule-stop watcher` row for pipeline starts. It carries current schedule timing evidence, reports backend watcher readiness for normal scheduled continuous starts, and marks `Ignore Schedule` continuous starts as high-review intentional bypasses.
- Completed now includes a manual backend-owned publish reconciliation panel. It calls `GET /api/publish-reconciliation` only when requested and correlates Completed Manifest rows, current Pending Publish rows, and the latest durable pending-drain summary.
- The new panel is evidence-only. It cannot mark done, repair, rerun, drain, delete, publish, rewrite manifests, or touch media.
- Exact normalized output/source path matches are treated as stronger evidence; same-leaf matches remain duplicate-title hints; missing completed outputs without exact pending/drain proof remain blockers.
- Settings `Backend Preview / Save Result` now has selectable detail rows for patch signature match, backend command status, warnings/errors, redacted diff, risk summary, backup path, and reload proof. This remains presentation-only over backend-owned Preview Patch / Save Patch commands.
- Queue, Completed, and Pending Publish status chips now disclose the 250-row WebView render cap as `250 shown / N filtered / M rows` when a large filtered set is only partially rendered.
- `Test-WebViewBrowserLargeTableSmoke.ps1` now verifies that disclosure in Chrome/Edge against injected 260-row Queue, Completed, and Pending Publish payloads, including filter warnings and hidden selected-row detail without posting mutation routes.
- `Test-WebViewBrowserMaintenanceReportsSmoke.ps1` now verifies Maintenance health/dry-run result rendering and Reports failure/audit triage in Chrome/Edge, including selected-row detail and read-only Launch/Diagnostics handoff navigation without posting mutation routes.
- Diagnostics `API Contract` now includes a read-only `Contract Safety Review` table that classifies auth, mutation, shell-open, preview/dry-run, read-only, contract-completeness, and frontend-ownership surfaces from `/api/contract`. `Test-WebViewBrowserDiagnosticsHandoffSmoke.ps1` verifies the safety summary/detail in Chrome/Edge while continuing to avoid mutation routes.
